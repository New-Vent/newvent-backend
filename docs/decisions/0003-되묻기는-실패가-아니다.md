# 0003. 되묻기(ASK_BACK)는 실패가 아닌 별도 상태로 둔다

- 상태: 적용됨
- 관련 코드: `generation/service/GenerationJob.Phase` · `editor/service/EditService`

## 문제

관리자가 "제목을 좀 더 눈에 띄게" 라고 썼는데 라우터가 **어느 블록을 어떻게 고칠지
정하지 못했습니다.** 또는 혜택 항목처럼 **관리자가 값을 정해야 하는** 것이 비어 있습니다.

이때 작업을 어떤 상태로 끝낼 것인가.

## 결정

`FAILED` 와 별개로 **`ASK_BACK`** 단계를 둡니다.

```java
DONE     ("완료",      100)
FAILED   ("실패",      100)
ASK_BACK ("확인 필요",  100)   ← 추가
CANCELLED("중단됨",    100)
```

## 이유

**관리자가 잘못한 게 없습니다.** `FAILED` 로 보내면 화면에 빨간 "실패" 가 뜹니다.
실제로는 "한 가지만 더 알려주시면 됩니다" 인데, 사용자는 자기가 뭘 망가뜨린 줄 압니다.

그리고 **`message` 의 뜻이 달라집니다.**

```
FAILED    message = 왜 안 됐는지 (오류)
ASK_BACK  message = 무엇을 알려달라는지 (질문)
```

둘을 같은 상태로 보내면 프론트가 구별할 수 없어 **질문을 빨간 오류로 그립니다.**

## 결과

**`done()` 에 반드시 포함해야 합니다.**

안 넣으면 프론트가 영원히 폴링합니다. 이 작업은 여기서 끝이고, **관리자의 답은 새 요청**
입니다. 같은 작업을 이어가는 게 아닙니다.

**프론트는 `phase` 로 분기해야 합니다.** `done == true` 만 보면 성공·실패·되묻기가 한
덩어리가 됩니다.

## 적용 범위 — 넓게 봐야 합니다

"관리자가 잘못한 게 없는데 할 수 없는 경우" 는 라우터 실패 말고도 있습니다.

```
요청대로 고쳤는데 화면이 한 글자도 안 바뀐 경우
  → "참여 버튼 영역에서 바꿀 수 있는 게 없습니다. 고를 수 있는 모양은 …"
```

이것도 **안내이지 오류가 아닙니다.** 모델은 자기가 못 한 걸 모르고 늘 뭔가를 출력하므로
서버가 전후를 비교해야 하는데, 그 결과를 `FAILED` 로 보내면 같은 문제가 반복됩니다.

## 하지 않기로 한 것

**모델에게 "못 하겠으면 말해라" 라고 시키지 않습니다.** 해봤고 안 됩니다. 모델은 자기가
무엇을 못 했는지 모르고, 항상 뭔가를 출력하며 "했다" 고 합니다. **서버가 전후를 대조하는
것만이 확실합니다.**
