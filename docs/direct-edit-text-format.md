# 직접 수정: 문구별 서식과 요소 삭제

## 처리 흐름

미리보기의 `editableTexts`에서 문구를 선택 → 문구·서식·삭제 변경을 화면에 임시 반영 → `변경 저장` → 기존 직접 수정 API를 한 번 호출 → 새 버전 하나 저장 → 미리보기와 문구 목록 재조회.

LLM 호출과 DB 스키마 변경은 없다. 기존 소유 권한·종료 이벤트·기준 버전 검사를 그대로 사용한다.

## API

`POST /api/admin/events/{eventId}/versions/direct-edit`

```json
{
  "sourceVersionId": 12,
  "edits": [
    {
      "index": 0,
      "before": "기존 제목",
      "after": "새 제목\n두 번째 줄",
      "format": { "color": "#d60076", "size": 24, "bold": true }
    },
    { "index": 3, "before": "불필요한 설명", "after": "불필요한 설명", "delete": true }
  ]
}
```

기존 `index`, `before`, `after` 요청도 그대로 처리한다. 서식만 변경하거나 삭제할 때도 `after`에는 기존 문구를 보내고, `before`는 서버 응답 그대로 사용한다.

| 필드 | 정책 |
| --- | --- |
| `format.color` | `#RRGGBB`, 대소문자 허용 |
| `format.size` | 정수 10~96, 단위 px |
| `format.bold` | true: 700, false: 400, 생략: 유지 |
| `format.reset` | 문구별 색·크기·굵기를 제거. 템플릿 및 상위 요소 서식은 유지 |
| `delete` | true: 문구 요소 삭제. 생략 또는 null: 삭제하지 않음 |

서식 필드를 생략하면 기존 값을 유지한다. `reset`과 서식을 함께 보내면 초기화 후 새 서식을 적용한다. 삭제 항목의 `after`·`format`은 적용하지 않는다.

## 미리보기 응답의 추가 정보

`editableTexts`의 각 항목은 기존 `index`, `before`에 다음 정보를 추가한다.

- `format`: 해당 문구 전용 span에 저장된 `color`, `font-size`, `font-weight` 값. 상속·계산된 CSS 전체가 아니다.
- `deleteDepth`: 원본 텍스트 노드의 부모에서 삭제 컨테이너까지의 부모 이동 횟수. 삭제 불가이면 null. 프론트 미리보기용이며 요청에는 보내지 않는다.

삭제 허용 여부와 범위는 서버가 원본 HTML에서 매번 다시 판단한다. 프론트는 삭제 가능 정보가 없는 구버전 응답에서는 삭제 버튼을 제공하지 않는다. 새 프론트보다 백엔드를 먼저 반영해야 한다.

## 삭제 범위와 보호 규칙

- 문구 하나만 담고 다른 기능이 없는 가장 바깥의 문구 컨테이너까지 삭제한다. 다른 문구·이미지가 있으면 그 앞에서 멈춘다.
- 블록 전체, 유의사항, CTA, 기간 슬롯, 동작 요소, 기능용 ID, 필수 큰 제목은 삭제하지 않는다.
- 레지스트리의 필수 요소·최소 항목 개수를 확인한다. 여러 삭제를 합쳤을 때 기준을 깨뜨리면 전체 요청을 거절한다.
- 여러 문구를 담은 카드 전체 삭제·블록 삭제·이미지 삭제는 이 기능의 대상이 아니다.
- 빈 문자열 저장은 기존처럼 빈 span과 인덱스를 유지한다. 요소 삭제는 저장 후 문구 수가 줄어들므로 **응답 이후 미리보기를 재조회하고 새 인덱스를 사용한다.**
- 요청 내 같은 인덱스 중복은 400, 기준 문구 불일치는 기존 409로 거절한다. 모든 대상을 원본 인덱스로 검증한 뒤 치환과 삭제를 적용한다.

## 프론트 동작

- 문구를 클릭하면 해당 문구가 강조되고 서식 도구가 열린다.
- 색상·크기·굵기는 문구 전체에 적용한다. 부분 글자 선택은 지원하지 않는다.
- 삭제 전 문구와 범위를 안내하고 확인을 받는다. 저장 전 삭제 취소가 가능하다.
- 삭제 미리보기는 요소를 숨겨 원본 노드·인덱스를 유지한다. 저장 HTML에서는 실제로 제거한다.
- 여러 변경을 모아 저장하고 새 버전을 조회한다. 실패 시 임시 편집 내용은 유지한다.
- 이후 AI 수정에서 서식이 유지되는지 강화하는 작업은 이번 범위에 포함하지 않는다.

## 검증 항목

- 템플릿 5종에서 문구별 서식·줄바꿈 저장, 서식 초기화, 빈 문구 재편집.
- 삭제와 다른 문구 수정을 원본 인덱스로 동시에 반영, 저장 후 새 인덱스로 재편집.
- 삭제 컨테이너 제거, 다른 문구·이미지 보존, 보호 요소 및 최소 개수 검사.
- 임의 CSS·범위 밖 크기·중복 인덱스·오래된 기준 문구 거절.
- 기존 JSON 요청 호환, 새 서식·삭제 JSON 수신, 여러 변경의 단일 버전 저장.
- 프론트 요청 묶음, 초기화, 삭제 확인 취소·삭제 취소, 크기 입력 검증.
