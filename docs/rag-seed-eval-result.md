# RAG 시드 기반 품질 평가 결과

시드 데이터 29건을 깔고 돌린 검색 품질 평가 결과를 정리한다.
원본 리포트: `build/rag-eval/` 최신 파일.

## 측정 조건

| 항목 | 값 |
|---|---|
| 색인 대상 | 템플릿 5종 + 시드 29건 (평가 시 모델별로 직접 임베딩) |
| 문항 | 40개 (일반 8 + negative 5 + 시드 27) |
| 판정 | 상위 3개 안에 기대 블록이 있으면 통과 (recall@3) |
| 거리 컷 | 0.5 초과 버림 |
| 통과 기준 | 30/40 (0.75) |

## 모델별 점수

| 모델 | 점수 | 판정 |
|---|---|---|
| bge-m3 | 32/40 | 통과 |
| cohere.embed-multilingual-v3 (운영 모델) | 32/40 | 통과 |
| mxbai-embed-large | 20/40 | 미달 |
| amazon.titan-embed-text-v2:0 | 19/40 | 미달 |

## 실패 패턴 분석

### negative 문항: 모델별 편차가 큼

"아무것도 안 나오면 정답"인데 모델마다 다르게 실패한다.
titan만 5개 전부 통과하는데, titan은 반대로 일반 문항을 21개나 틀린다
(보수적이라 안 뱉는 쪽으로 치우침). negative는 모델 실력보다
거리 컷(0.5) 설정 문제다.

| 모델 | negative 실패 | 통과 |
|---|---|---|
| bge-m3 | 4개 (유의사항, xyz123, 당첨자발표일, 문의처) | 주식 |
| cohere | 4개 (유의사항, 주식, 당첨자발표일, 문의처) | xyz123 |
| titan | 0개 | 5개 전부 |

### cta 쏠림

"참여", "쿠폰 받기" 같은 2~5글자 짧은 cta 청크가 시드마다 반복돼서
짧은 쿼리("참여 방법", "할인 쿠폰")의 상위권을 싹쓸이한다.
모호한 질문 7개는 구체형으로 바꿨다 (예: "참여 방법" → "참여 절차를 순서대로 알려줘").
그래도 안 되는 건 시드 문구 쪽 문제로 보고 개별 손본다.

### 모델별 특이

- bge-m3: negative 4개 실패. 일반 문항은 가장 고름
- cohere: negative 4개 실패 (xyz123은 통과). 일반 문항은 bge와 동점
- mxbai/titan/snowflake: 일반 문항 탈락이 많아 운영 후보에서 제외

## 중요 발견: cohere 측정 오염

cohere 결과에만 같은 청크가 2개씩 나온다 ("최소 구성..." ×2, "축제 안내 보기" ×2 등).
원인: dev DB에 `seedRagData`로 커밋된 시드 청크(cohere 벡터)가 있는데,
평가가 같은 내용을 같은 모델로 또 색인해서 중복 집계됐다.
다른 모델은 모델명 필터에 걸려 오염 없음.

영향: 중복이 top-3 자리를 먹어서 cohere 점수는 저평가됐을 가능성이 크다.
대응: 빈 DB에서 평가만 돌려 재측정한다 (`down -v` → migrate → 평가, `seedRagData` 없이).
평가 하네스는 스스로 색인하므로 시드 적재 없이도 돈다.

## 결론

- 게이트(30/40) 통과. bge-m3와 cohere 동점
- 동점이므로 교체 비용(전체 재색인 + Ollama 운영 부담) 감안해 **cohere 유지**
- 단 cohere 점수는 오염 상태라, 깨끗한 DB에서 재측정 후 최종 확정한다
